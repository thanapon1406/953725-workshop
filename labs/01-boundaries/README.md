# Lab 01 — Boundary of Test Cases (ระบบเลือกตั้ง VOTER)

**อ้างอิง:** Toby Clemson, [Testing Strategies in a Microservice Architecture](https://martinfowler.com/articles/microservice-testing/)

## เป้าหมาย

นำ `test-cases.md` (Lab 00 ข้อ 5) ที่เตรียมไว้ มาติด **Boundary** ของแต่ละ test ว่าอยู่ระดับไหน

| Boundary | คืออะไร | เราใช้ตรงไหน |
|---|---|---|
| **U** | Unit — logic เล็ก, collaborator เป็น test double | `test/unit/thaiNationalId.test.ts` |
| **I** | Integration — คุยกับ DB/HTTP จริง | unit + Postgres จริง |
| **C** | Component — ทดสอบ service ผ่าน HTTP | `test/integration/` (supertest + Postgres) |
| **E** | End-to-end — ระบบทั้งหมดเหมือน production | `e2e/` (Playwright) |
| **X** | ไม่ใช่ automated functional test | — |

| TC-03 | ผู้มีสิทธิในเขต CM-1 | ลงทะเบียนด้วยเขตเลือกตั้งที่ไม่มีในระบบ | ระบบปฏิเสธด้วย 400 และไม่สร้างบัญชี | **I** |
| TC-04 | ผู้มีสิทธิในเขต CM-1 | ลงทะเบียนสำเร็จด้วยข้อมูลครบถ้วน | ระบบสร้างบัญชีและส่งสิทธิ์ token กลับ | **I** |
| TC-05 | ผู้ใช้ที่ไม่เคยลงทะเบียน | login ด้วยเลขบัตรที่ไม่เคยเก็บ | ระบบปฏิเสธด้วย 401 | **I** |

| TC-09 | ผู้มีสิทธิที่เลือกหมายเลข 2 ไปแล้ว | เปลี่ยนคะแนนเป็นหมายเลข 3 | ระบบอัปเดตเป็นหมายเลข 3 และไม่นับหมายเลข 2 ซ้ำอีก | **C** |
| TC-10 | ผู้มีสิทธิในเขต CM-1 | ลงคะแนนให้ผู้สมัครของเขต CM-2 | ระบบปฏิเสธ เพราะไม่ใช่ผู้สมัครในเขตของตัวเอง | **C** |
